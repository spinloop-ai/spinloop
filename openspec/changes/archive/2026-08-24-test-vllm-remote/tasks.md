Healthy 08-23 23:53Z; MTP drafter up ("Detected MTP model, sharing lm_head"), tool parser accepted. Three engine-side fixes found live along the way, all now in the preset: `attention-backend = TRITON_ATTN` (the default FlashInfer JIT-needs-nvcc, absent on the slim AMI — first-request crash), `kv-cache-dtype = fp8` (13.55 GiB full-precision KV would not fit the 8.28 GiB profiled at 196608), `max-num-seqs = 128` (the model's GDN layers keep a mamba state per sequence; the 0.92 budget profiles 158 blocks and CUDA graph capture refuses max_num_seqs 256). NOTE: the AMI's daemon binary predates vLLM's parallel support — it drops `parallel` from a pushed deploy config, so a future `spinloop remote deploy` (which moves max-num-seqs into `parallel` and drops it from serveArgs) will break the engine until the AMI is rebaked; the working stopgap is a `--max-num-seqs 128` entry in the SSM parameter's serveArgs
